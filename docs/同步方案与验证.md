# 同步方案与验证

[English](sync-design.md) | **简体中文**

## 合并与重试

同步采用服务器版本校验、三方合并和持久化待上传状态，支持离线修改及恢复联网后的重试。

三方合并比较“上次已确认的状态”“本机当前状态”“服务器最新状态”。只有本机实际改变的字段才成为本机的写入意图，不能把所有旧内容反复覆盖回去。

`SixSync.Engine` 保存基线、当前状态和未确认的写入 ID。写入在数据库事务中锁住房间并检查递增版本，冲突时返回最新状态重试。成功写入 ID 保留在服务器，用于处理“写入成功、响应丢失”的重试，避免旧请求覆盖较新的修改。

删除优先于对同一任务的并发编辑；不同字段或任务合并；同一字段冲突由后来成功的提交决定。显式清空使用单独标记，以清除其他设备尚未上传的旧内容。通知权限不跨设备同步。

## 配对与权限

房间成员独立于邀请记录，因此第三台及更多设备不会替换原有成员。邀请为随机 12 位十六进制码，服务器验证有效期、单次消费及匿名身份。发起端创建房间后直接参与同步，不能依赖某一个 Realtime 事件才能连接。

浏览器只可读取自己参与的房间，不能直接修改表，也不能枚举邀请。写入和加入只经过检查身份的 RPC。Realtime 用来加速，轮询与联网/回前台事件负责补偿。

## 部署后的验证

- `npm test`：真实合并模块和应用接口，覆盖删除、设置、一次机会状态、显式清空、并发新增、同字段冲突、上传途中编辑、丢失响应、重开后重试、旧房间响应隔离、身份恢复和错误反馈。
- `npm run test:db`：真实 PostgreSQL，覆盖三成员、过期/已用邀请、竞争消费、跨用户读写隔离、原子版本校验、幂等重试和旧房间迁移。运行时创建并销毁专用测试数据库。
- 浏览器验证：使用三个独立测试环境，通过界面检查配对、新增与删除传播、设置同步、离线重开及恢复联网。应分别验证目标浏览器；本地 Chromium 测试不能代替 iPhone/Safari 真机测试。

本地测试不能代替实际部署后的验证；数据库迁移与网站发布需分别完成，上线顺序见 [部署与发布](部署与发布.md)。
